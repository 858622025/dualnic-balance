# 消息目录

> 全项目所有用户可见文本与运行日志的唯一文案来源是 `lang/` 语言目录（SC / TC / en / ja）。
> 代码不写裸文本——调用点用 `dualnic_core::msgref!` 宏或 `crates/gui/src/msgs.rs` 常量；
> 本文登记消息类划分、参数语义与新增消息的流程。

## 消息模式

- **标识**：`msgid`（消息类，按模块分组）+ `msgno`（类内消息号，三位数字）。
- **模板**：语言文件中 `msgno = 文本模板`，占位符 `&1..&9` = 第 n 个参数（msgv1..n）。
- **渲染**：`MessageRef { msgid, msgno, args }` → 沿兜底链解析 → 显示文本。
- **兜底链**：当前语言 → 兜底语言（languages.ini **列表第一个**）→ 消息代码原文
  （`DNREC-001(v1, v2)`）。
- **语言装载**：`lang/languages.ini` 是唯一语言清单，代码零写死；启动时按清单**动态预载
  全部语言**（`lang/<code>.ini`，缺失回退出厂内置包 `FACTORY_PACKS`，仅 SC/en）；
  语言代码**一律 2 字符**（SC=简体中文、TC=繁體中文、en=English、ja=日本語），
  非 2 字符的行跳过。**新增语言 = languages.ini 加一行 + 放一个 2 字符代码的 ini 文件**，
  无需改代码。
- **载入校验**：`install()` 返回告警列表——以**出厂内嵌 SC 包**（与二进制同版本）为基准，
  比对每个已装载目录每 msgid 的（**词条数 + 最大消息号**）。尾部落后（旧 lang 配新 exe）
  由最大号抓；**中间跳号由词条数差抓**；多出的词条不报（向前兼容）。服务进程告警落
  日志文件、GUI 落调试控制台；缺失项渲染时自动回退兜底语言，不影响使用。
- **代码**：`core/src/msg.rs`（类型/解析/填充/运行时/校验）；GUI 侧统一入口
  `crate::i18n::tr(msgs::常量, args)`。
- **语言策略**：GUI 按界面语言渲染一切可见文本与错误；服务进程固定 SC（日志输出为中文）；
  事件先以结构化引用落库、显示时按语言渲染；诊断报告跟随 GUI 语言。

## 新增一条消息的流程

1. 在对应 msgid 领一个 msgno（类内递增，不复用废弃号）；
2. `lang/SC.ini` 与 `lang/en.ini`（及 TC/ja）**同步**加词条（模板里 `&1..&n` 与参数一一对应）；
3. 代码调用点：`msgref!("DNREC", 1; "3", "2", "1", "0")`；同一消息多处使用时在
   `crates/gui/src/msgs.rs` 登记常量；
4. 跑完整性审计（代码引用 vs 四语言目录，应零缺失）；参数或键全缺时自动回退代码原文，
   不会 panic——但不要依赖该兜底交付。

### DNERR（错误链）

错误以 `CoreError::Msg(MessageRef)` 结构化（Display 走 `msg::t`，服务进程装 SC 目录 →
日志保持中文；`message()` 供 IPC 跨语言传递）；IPC 层 `RpcError` 与五个错误字段
（`load_error` / `read_error`×3 / `command_error`）以 `MessageRef` 传递，GUI 按**自己的**
界面语言渲染；GUI 本地错误在构造点渲染。**领号前先看 `lang/SC.ini` 的 [DNERR] 节**
（词条权威源）。分区：

| 号段 | 区域 |
|---|---|
| 1-5 | CoreError 基础变体（InvalidAddress/MissingRole/NoAdapterMatched/AmbiguousRole/Config 包裹） |
| 10-13 | CIDR 解析（ip.rs） |
| 20-30 | 配置校验/容器解析（config.rs） |
| 50-52 | 路由意图网关（intent.rs）与角色仲裁（role.rs：052 同卡、004 含块数） |
| 60-63 | IPC 帧错误（ipc.rs） |
| 70-71 | 网络枚举（net.rs） |
| 74-81 | SQLite（db.rs） |
| 83-102 | 状态/方案操作/平台（status.rs、server.rs） |
| 110-111 | IPC 服务器（server.rs） |
| 120-143 | GUI 本地（client.rs、i18n.rs） |

### DNLOG（日志与诊断）

服务日志（tracing/eprintln）全部走 `msg::t` 渲染——服务进程装 SC 目录，**日志输出为
中文**，但源码不含硬编码文案；诊断字段以 `MessageRef` 传递（`ReconcileStep.detail`、
`EnvCandidate.reason`、`MatchResult.reason`，GUI 可按界面语言渲染）；意图描述、语言校验
告警、headless 输出同源。**领号看 `lang/SC.ini` [DNLOG]**（82 条，含 67/68 中性词条）。
分区：

| 号段 | 区域 |
|---|---|
| 1-19 | 服务壳（main/scm/db） |
| 20-27 | 状态与迁移 |
| 30-34 | 网络枚举 |
| 40-55 | 对账与 metric |
| 60-68 | 对账步骤明细（67/68 为中性词条） |
| 70-78 | watch 与 IPC 服务器 |
| 80-87 | core 诊断与意图描述 |
| 90-92 | 语言文件校验 |
| 100-104 | GUI 本地 |

## 刻意保留的非目录文本

以下为**数据而非文案**（存入配置/DB，翻译会导致跨语言名称漂移）：
`DEFAULT_PROFILE_NAME`「默认」、GUI 生成的方案名（「新方案」「(副本)」）、网段备注前缀
（「自动：」「手工采纳」）、自动方案名部件（「环境-」「无网关」「无内网」）；
另有 `setup.rs` 的 Transcript 行过滤标记（匹配中文系统 PowerShell 输出的功能性字符串）。
